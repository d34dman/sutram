For app authors With or without WebMCP

Let agents use your web app through commands, not clicks.

Sutram gives your app one standard way to expose what it can do. Agents call your commands as WebMCP tools, from JavaScript in a headless browser, or by typing into a terminal-like console. People can use the same console.

$ npm i @d34dman/sutram

You register commands once. Sutram exposes them four ways, with the same schema, checks, handler and exit codes behind each one.

WebMCP tools

browsers with WebMCP

01

Each command becomes a tool with its JSON Schema and hints such as read-only or ask-first, and the list follows the page as commands come and go.

JavaScript in the page

02

Sutram.tools() returns what a WebMCP agent would see, and Sutram.call() runs a tool. Consequential tools run only with { confirmed: true }.

await page.evaluate(() =>
  Sutram.call("cart_add", { sku: "V60-02", qty: 2 }));

      How it works
      
    One definition, every shape
    
      
    A command is a name, a JSON Schema for its input, and a function. Sutram turns it into a tool for agents and a command line that agents and people can type. Your handler never knows who called it.
    
      
    

    Sutram.register({
  name: "cart add",
  provider: "cart",
  description: "Add a product to the cart",
  input: {                         // JSON Schema
    type: "object",
    properties: {
      sku: { type: "string" },
      qty: { type: "integer", minimum: 1, default: 1 },
    },
    required: ["sku"],
  },
  positional: ["sku", "qty"],
  annotations: {},                 // readOnly, consequential, …
  run: ({ sku, qty }) => cart.add(sku, qty),
});
    
        
    
          
    
            
    Typed into the console
    

    › cart add V60-02 2
› cart add --sku=V60-02 --qty=2
› cart add -h
› man cart add
    
          
    
          
    
            
    Called as a tool
    

    cart_add({ "sku": "V60-02", "qty": 2 })          // WebMCP
Sutram.call("cart_add", { sku: "V60-02", qty: 2 }) // JavaScript
// same schema, same checks, same handler
    
          
    
        
    
      
    
    
    
  
    

  
    
    
    
      Features
      
    Everything a command line should have
    
      
    You write the commands. Sutram does the rest, the same way for every app on the page.
    
      
    
        
    Agents without screenshots
    Agents call your app's own logic instead of reading pixels and guessing which button to click. Results come back as data.
    WebMCP · Sutram.call()
    
        
    Asks before it matters
    Mark a command consequential. The console asks, WebMCP hosts get the hint, and Sutram.call() waits for confirmed: true.
    readOnly · consequential
    
        
    Agents learn the app
    Help, manual pages and a status of the whole page are generated from your definitions, so they always match what the page can do right now.
    help · man · status
    
        
    The user's session, nothing more
    Commands run in the browser and call your own endpoints, so they can do exactly what the user could already do.
    no new API
    
        
    Data for agents, tables for people
    Return data. Agents and --json get it exactly as you returned it; people get tables and key: value lines.
    --json · --wide
    
        
    Small and plain
    ES modules, or one file from a CDN. A web component for the console. Works with any framework, or none.
    0 dependencies
    
      
    
    
    
  
    

  
    
    
    
      Why commands
      
    A standard interface, not screenshots
    
      
    Without Sutram, an agent reads the page, guesses which elements to click, and reads it again to see whether it worked. With Sutram, every part of the app hooks in the same way, and agents get one short list of commands, in the user's own logged-in session.
    
      
    

    # the form grows as it is filled in
› form request set topic billing
topic set. The form now also asks for: invoice, amount.
› form request set invoice 2024-17
form request set: "2024-17" is not a valid invoice number.
Use INV- and at least four digits, such as INV-20417.
› form request set invoice INV-20417
invoice set.
    
        
    
          
    In the user's session
    The person logs in, the agent takes over. It can do exactly what the person could, through no new API.
    
          
    The same everywhere
    Headless browser, WebMCP, JavaScript in the page or a chat assistant: the same commands and the same answers.
    
          
    Cheaper by far
    On Drupal's article form, reading the page costs a browser agent 2.5 to 5 times more, and correcting one wrong value about 3,300 tokens against 17 to 44 with Sutram.

      Get started
      
    Up and running in a minute
    
      
    No build step needed. Paste this into an HTML file and open it.
    
      
    
        
    
          
    
            
    Load Sutram
    
            
    From the CDN, or install @d34dman/sutram from npm and import it.
    
            
    <script type="module">
  import Sutram from "https://cdn.jsdelivr.net/npm/@d34dman/sutram@0.4/dist/sutram.js";
</script>
    
          
    
        
    
        
    
          
    
            
    Register a command
    
            
    Give it a name, an input schema and a function.
    
            
    Sutram.register({
  name: "hello world",
  provider: "hello",
  description: "Say hello",
  input: { type: "object", properties: { who: { type: "string", default: "you" } } },
  positional: ["who"],
  annotations: { readOnly: true },
  run: ({ who }) => ({ text: `Hello, ${who}.` }),
});
Sutram.mountConsole();
    
          
    
        
    
        
    
          
    
            
    Call it
    
            
    Press ` and type hello world Ada. In a browser with WebMCP, agents get a hello_world tool. From a headless browser or DevTools:
    
            
    await Sutram.call("hello_world", { who: "Ada" });
// → { code: 0, text: "Hello, Ada." }
