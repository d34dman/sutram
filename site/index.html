    One definition, two shapes
    
      
    A command is a name, a JSON Schema for its input, and a function. Sutram turns it into a command line for people and a tool for agents. Your handler never knows who called it.
    
      
    

    Sutram.register({
  name: "cart add",
  provider: "cart",
  description: "Add a product to the cart",
  input: {                         // JSON Schema
    type: "object",
    properties: {
      sku: { type: "string" },
      qty: { type: "integer", minimum: 1, default: 1 },
    },
    required: ["sku"],
  },
  positional: ["sku", "qty"],
  annotations: {},                 // readOnly, consequential, …
  run: ({ sku, qty }) => cart.add(sku, qty),
});
    
        
    
          
    
            
    A person types
    

    › cart add V60-02 2
› cart add --sku=V60-02 --qty=2
› cart add -h
› man cart add
    
          
    
          
    
            
    An agent calls
    

    cart_add({ "sku": "V60-02", "qty": 2 })
// same schema, same checks, same handler
    
          
    
        
    
      
    
    
    
  
    

  
    
    
    
      
    Everything a command line should have
    
      
    You write the commands. Sutram does the rest, the same way for every app on the page.
    
      
    
        
    help · man · status
    Discovery built in
    Help and manual pages are generated from your definitions, so they always match what the page can do right now.
    
        
    read-only · consequential
    Asks before it matters
    Mark a command consequential and the console asks first. Agent hosts get the same hint and can ask the user too.
    
        
    WebMCP
    Agents without screenshots
    Every command becomes a WebMCP tool with its JSON Schema. Agents call your app's logic instead of clicking around.
    
        
    no new API
    The user's session, nothing more
    Commands run in the browser and call your own endpoints, so they can do exactly what the user could already do.
    
        
    --json · --wide
    Data in, tables out
    Return data. People get tables and key: value lines; agents and --json get the data exactly as you returned it.
    
        
    0 dependencies
    Small and plain
    ES modules, or one 68 kB file from a CDN. A web component for the console. Works with any framework, or none.
    
      
    
    
    
  
    

  
    
    
    
      
    Get started in a minute
    
      
    No build step needed. Paste this into an HTML file and open it.
    
      
    
        
    
          
    
            
    Load Sutram
    
            
    From the CDN, or install @d34dman/sutram from npm and import it.
    
            
    <script type="module">
  import Sutram from "https://cdn.jsdelivr.net/npm/@d34dman/sutram@0.2/dist/sutram.js";
</script>
    
          
    
        
    
        
    
          
    
            
    Register a command
    
            
    Give it a name, an input schema and a function.
    
            
    Sutram.register({
  name: "hello world",
  provider: "hello",
  description: "Say hello",
  input: { type: "object", properties: { who: { type: "string", default: "you" } } },
  positional: ["who"],
  annotations: { readOnly: true },
  run: ({ who }) => ({ text: `Hello, ${who}.` }),
});
Sutram.mountConsole();
    
          
    
        
    
        
    
          
    
            
    Press `
    
            
    Type help, then hello world Ada. In a browser with WebMCP, agents can call hello_world too.
